You don’t need React to build an Excalidraw-like app. What you need is:

* a rendering engine (Canvas or SVG),
* a scene graph (your “elements” array),
* pointer-driven interaction logic (create / update / select / transform),
* view transform (pan/zoom),
* history (undo/redo),
* export/import.

If you do those cleanly, the framework barely matters. Svelte is fine.

## Pick your rendering approach (do this first)

### Option A (recommended): `<canvas>` + roughjs

Best match for Excalidraw: fast, simple to pan/zoom, easy to export to PNG.

* **roughjs**: “hand-drawn” strokes/shapes
* **perfect-freehand** (optional): nicer pen strokes
* You draw everything every frame (or whenever state changes)

### Option B: SVG

Easier DOM-level hit testing and editing, but can get heavy with many elements.

### Option C: Konva/Fabric wrappers

You’ll move faster at first, but you’ll fight the abstraction once you want Excalidraw-like behavior. I’d avoid unless you’re prototyping.

## Start with an MVP toolset

Don’t try to clone all of Excalidraw at once. Ship this first:

1. rectangle, ellipse, line, arrow
2. selection + move
3. resize (corners)
4. pan (space or middle mouse) + zoom (wheel)
5. undo/redo
6. save/load JSON
7. export PNG

Text, binding arrows, multi-select, groups, collaboration—later.

## Your core data model (scene graph)

Keep it boring and explicit:

```ts
export type ElementType = 'rect' | 'ellipse' | 'line' | 'arrow' | 'freehand' | 'text';

export type ExcalElement = {
  id: string;
  type: ElementType;
  x: number;
  y: number;
  w: number;
  h: number;
  points?: { x: number; y: number }[]; // for line/freehand in local coords
  angle?: number;

  stroke: string;
  fill?: string;
  strokeWidth: number;
  roughness: number;

  // cache for performance (optional)
  version: number;
};
```

Store “world coordinates” in elements. Keep view transform (scroll/zoom) separate.

## Svelte stores for state

Use stores for scene + app state + history.

```ts
import { writable, get } from 'svelte/store';

export const elements = writable<ExcalElement[]>([]);
export const appState = writable({
  tool: 'select' as 'select' | 'rect' | 'ellipse' | 'line' | 'arrow' | 'freehand' | 'text',
  selectedIds: new Set<string>(),
  zoom: 1,
  scrollX: 0,
  scrollY: 0
});

type Snapshot = { elements: ExcalElement[]; appState: any };
const undoStack = writable<Snapshot[]>([]);
const redoStack = writable<Snapshot[]>([]);

export function pushHistory() {
  undoStack.update(s => [...s, { elements: structuredClone(get(elements)), appState: structuredClone(get(appState)) }]);
  redoStack.set([]);
}
```

Opinionated take: **snapshot history** is simplest and good enough until you hit performance limits. If you later need it, switch to command-based diffs.

## The view transform (pan/zoom) that won’t make you miserable

Two helper functions:

```ts
export function worldToScreen(wx: number, wy: number, st: any) {
  return { x: (wx + st.scrollX) * st.zoom, y: (wy + st.scrollY) * st.zoom };
}
export function screenToWorld(sx: number, sy: number, st: any) {
  return { x: sx / st.zoom - st.scrollX, y: sy / st.zoom - st.scrollY };
}
```

When drawing on canvas:

```ts
ctx.setTransform(st.zoom, 0, 0, st.zoom, st.scrollX * st.zoom, st.scrollY * st.zoom);
```

Everything you draw uses world coords; the transform handles the rest.

## Rendering loop (Canvas + roughjs)

Render whenever elements/appState changes (or via rAF). Minimal pattern:

```svelte
<canvas bind:this={canvas} class="stage" />

<script lang="ts">
  import { onMount } from 'svelte';
  import rough from 'roughjs/bin/rough';
  import { elements, appState } from './stores';
  import { get } from 'svelte/store';

  let canvas: HTMLCanvasElement;
  let ctx: CanvasRenderingContext2D;
  let rc: any;

  function resize() {
    const dpr = devicePixelRatio || 1;
    canvas.width = canvas.clientWidth * dpr;
    canvas.height = canvas.clientHeight * dpr;
    ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
  }

  function draw() {
    const els = get(elements);
    const st = get(appState);

    // clear in screen space
    ctx.setTransform(1,0,0,1,0,0);
    ctx.clearRect(0, 0, canvas.width, canvas.height);

    // world transform (also account for dpr already applied by ctx transform above if you do it differently)
    ctx.setTransform(st.zoom, 0, 0, st.zoom, st.scrollX * st.zoom, st.scrollY * st.zoom);

    for (const el of els) {
      // roughjs draws in current ctx transform
      switch (el.type) {
        case 'rect':
          rc.rectangle(el.x, el.y, el.w, el.h, { roughness: el.roughness, stroke: el.stroke, strokeWidth: el.strokeWidth, fill: el.fill });
          break;
        case 'ellipse':
          rc.ellipse(el.x + el.w/2, el.y + el.h/2, Math.abs(el.w), Math.abs(el.h), { roughness: el.roughness, stroke: el.stroke, strokeWidth: el.strokeWidth, fill: el.fill });
          break;
        case 'line': {
          const p0 = el.points?.[0], p1 = el.points?.[1];
          if (p0 && p1) rc.line(el.x + p0.x, el.y + p0.y, el.x + p1.x, el.y + p1.y, { roughness: el.roughness, stroke: el.stroke, strokeWidth: el.strokeWidth });
          break;
        }
      }
    }
  }

  onMount(() => {
    ctx = canvas.getContext('2d')!;
    rc = rough.canvas(canvas);
    resize();
    const ro = new ResizeObserver(() => { resize(); draw(); });
    ro.observe(canvas);

    const unsub1 = elements.subscribe(draw);
    const unsub2 = appState.subscribe(draw);
    return () => { ro.disconnect(); unsub1(); unsub2(); };
  });
</script>

<style>
  .stage { width: 100vw; height: 100vh; display:block; }
</style>
```

That’s enough to see shapes.

## Pointer interaction (the real “clone” work)

You need a simple interaction state machine:

* `idle`
* `drawing` (creating new element)
* `dragging` (move selection)
* `resizing` (drag handle)
* `panning`

Skeleton:

```ts
let interaction:
  | { mode: 'idle' }
  | { mode: 'drawing'; id: string; origin: {x:number;y:number} }
  | { mode: 'dragging'; start: {x:number;y:number}; initial: Map<string,{x:number;y:number}> }
  | { mode: 'panning'; start: {x:number;y:number}; initialScroll: {x:number;y:number} }
  = { mode: 'idle' };
```

### Drawing a rectangle example

* pointerdown: create element with `w=0,h=0`, set mode drawing
* pointermove: update `w/h` from origin to current
* pointerup: normalize (ensure w/h positive by adjusting x/y), push history

Key detail: **convert screen -> world** immediately on input, and only use world coords internally.

## Hit testing (selection)

Excalidraw feels good because selection is reliable. You’ll need per-element hit tests:

* Rect/ellipse: bounding box is fine to start
* Line/arrow: distance-to-segment with a tolerance scaled by zoom
* Freehand: iterate segments

Start crude, refine later.

Distance-to-segment (core for lines):

```ts
function distToSegment(px, py, ax, ay, bx, by) {
  const abx = bx-ax, aby = by-ay;
  const apx = px-ax, apy = py-ay;
  const ab2 = abx*abx + aby*aby;
  const t = ab2 ? Math.max(0, Math.min(1, (apx*abx + apy*aby)/ab2)) : 0;
  const cx = ax + t*abx, cy = ay + t*aby;
  const dx = px-cx, dy = py-cy;
  return Math.sqrt(dx*dx + dy*dy);
}
```

Tolerance should be something like `8 / zoom`.

## Resizing with handles

Compute 8 handle points from the selected element’s bounds. On drag:

* update `x,y,w,h` based on which handle
* optionally preserve aspect ratio when shift is held

This is fiddly but straightforward.

## Text editing (harder than it looks)

Don’t draw text directly on canvas while editing. Overlay an HTML `<textarea>` positioned using `worldToScreen()`. On blur/enter, commit to element and render text onto canvas.

## Performance tricks you’ll want sooner than you think

* Cache roughjs drawable ops per element (`version`-based). Re-generate only when element changes.
* Maintain a spatial index (simple grid or quadtree) for hit testing once elements > a few hundred.
* Avoid store updates on every pixel move for everything; update only the active element while drawing.

## File format & export

* Save/load: `JSON.stringify(elements)`
* Export PNG: render to an offscreen canvas at desired scale, then `toDataURL()` / blob download.
* Export SVG: roughjs can output SVG too, but you’ll need a parallel exporter.
